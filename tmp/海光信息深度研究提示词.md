## 四、报告正文必须覆盖的研究模块

报告必须按以下结构组织（可增小节，不可删主模块）。每一模块结尾给出 **本节结论（1–3 条，必须可证伪）**。

### 模块 A｜投资摘要（先写结论）
- 一句话投资判断：买入/增持观望/中性/回避（选一，并给 12 个月视角）
- 核心矛盾 3 条（不是亮点罗列；必须触及 CPU 与 DCU 的量价/生态/竞争中至少两项）
- 预期差分值：市场定价 vs 你的基本面判断（高估/合理/低估 + 幅度区间）
- 关键 2028 中性情景目标市值与隐含回报（相对当前市值）
- 最可能证伪你论点的 2 个观察点（建议绑定：下一代 CPU/DCU 导入节奏、毛利率、存货/合同负债、关键客户订单）

### 模块 B｜业务与壁垒
必须回答：
1. 收入与利润的真实驱动拆分：海光 CPU vs 深算 DCU vs 其他；历史占比演变；利润贡献是否与收入占比背离（高毛利产品是否真正贡献增量利润）
2. 产品与价值创造：架构路线（x86 兼容 CPU、DCU 指令集/软件栈路径）、制程与封装约束、IP/授权与自主设计边界；用披露数据界定“技术同源”与“自主迭代”各自证据强度
3. 护城河类型排序（生态与软件兼容、客户认证与信创名录、性能/能效代际、供应链与流片能力、与整机厂绑定、品牌与切换成本等），每条给证据强度：强/中/弱
4. 客户集中度与议价权：行业/客户类型集中度；若公开数据不足，用逻辑上下界说明，禁止编造具体客户份额或未公开中标金额
5. 可复制性：竞品 3–5 年能否追上关键生态与性能窗口；卡点在生态、工艺、人才、资本还是客户关系
6. 与中科曙光及其他关联方的协同、关联交易规模与公允性边界（用披露数据说话）；评估“绑定整机”是护城河还是单一依赖风险

拒绝：空泛的“国产算力龙头”“自主可控平台”而无产品代际、毛利、研发产出证据。

### 模块 C｜经营战略与执行
必须回答：
1. 公司过去 3–5 年战略主线演变（CPU 为主 → CPU+DCU 双轮；通用服务器 vs AI 训练/推理）
2. 研发费用率、资本开支、存货结构（原材料/在产品/库存商品）、流片与工程样片相关表述是否匹配战略
3. 管理层激励、股权结构稳定性、关键人事与核心技术人员变化（有则分析，无则注明未见）
4. 指引 vs 实际：最近 8 个季度或最近 3 年，超预期/低于预期的次数与原因归类（产品放量、毛利波动、费用、存货减值等）
5. 执行评分：战略清晰度、资源配置效率、产品兑现能力、生态建设进度（各 1–5 分 + 理由）

### 模块 D｜深度财务体检
以最新年报/半年报/季报为主，构建至少 3–5 年趋势：
1. 增长：收入、毛利、经营利润、归母净利润、扣非、经营现金流（OCF）、自由现金流（FCF）
2. 盈利质量：综合毛利率与分产品毛利率（能拆则拆）；费用率（研发/销售/管理）；资产减值、存货跌价、信用减值
3. 资产负债表：应收账款与存货周转、合同负债/预收款、货币资金与理财、有息负债、商誉与长期资产、研发资本化（若有）
4. ROIC / ROE 杜邦与投入资本回报；高研发模式下“利润好看但现金差”或相反情况的识别
5. 现金流转换：净利润 → OCF → FCF 的漏损点（存货囤积、应收扩张、预付款、关联方占用等）
6. 分红分析：同比/环比异常科目必须解释（`china-variance-commentary` 思维）；重点盯毛利率跳变、存货与合同负债背离、研发费用率与收入增速背离
7. 会计与披露质量：收入确认、关联交易、分部/产品披露是否足够支撑业务结论

输出一张“财务健康度评分卡”（流动性、杠杆、盈利质量、现金流、增长可持续性、存货健康度）。

必须回答：
1. 行业本质：国产 CPU 与 AI 加速器分别是政策驱动、性能窗口驱动、还是存量替换+增量 AI 双驱动；周期属性与库存牛鞭效应

4. 供给与竞争：国际巨头可获得性变化、国产 CPU 多路线并存、国产 GPU/DCU 玩家扩产与同质化风险
5. 公司位势：在 x86 兼容国产 CPU 中的相对位置；DCU 相对寒武纪等的差异化（训练/推理、生态、出货场景）；生态软件数量/适配进度（有公开数据则引用，无则标注信息缺口）
6. 未来 3 年行业量价框架：CPU 出货量与 ASP、DCU 出货量与 ASP、毛利率弹性来源（规模、良率、产品结构、竞争降价）

### 模块 F｜各业务模块发展（必须分业务写）

## 五、写作与论证纪律

1. **拒绝宏观政策套话**：不得用大段产业政策、规划文件复述代替公司基本面；政策若提及，只能作为单一外生变量并量化影响边界（例如对某类招标份额的上下界假设），禁止“政策支持所以长期看好”式空转
2. **数据必须引用最新来源**：优先最新定期报告与最近交易日行情；旧数据需注明日期
3. **逻辑推演优先**：每个判断写清“因为 A（数据）→ 所以 B（机制）→ 因此 C（对利润/估值影响）”
4. **结论必须明确**：禁止“整体看好但仍需观察”作为最终结论；若信息不足，明确写“信息不足，暂给中性，缺口是……”
5. **不编造**：无披露的客户份额、未公开订单金额、未证实的对标 NVIDIA 性能倍数、未公开良率等，只能给区间假设并标注为假设
6. **矛盾处理**：年报 vs 研报 vs 新闻冲突时，以法定披露为准，并解释卖方可能偏差
7. **数字可稽核**：关键表格中的合计、同比、利润率计算必须自洽；CPU+DCU 分拆加总须等于总收入（或明确“其他”残差）
8. **篇幅建议**：正文建议 8000–20000 字等价信息量；预期差与三情景估值不得短于业务介绍
9. **术语纪律**：首次出现的 DCU、x86 兼容、ROCm/CUDA 生态替代等给出一句精确定义；此后保持口径一致
